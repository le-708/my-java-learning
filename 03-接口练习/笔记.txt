1,
Mouse 和 Keyboard 是完全没有关系的两个类，为什么能用同一个 USB[] 数组来存？
答案：因为它们都“签了同一份合同”——实现了 USB 接口。

在 Java 里，一个类一旦 implements USB，它就获得了一个第二身份：它既是它自己（Mouse/Keyboard），也是一个 USB 类型的东西。

USB[] 数组要求里面放的是“有 USB 身份的东西”，而不是某个具体的类。所以 Mouse 和 Keyboard 虽然彼此没有继承关系，但都满足这个身份要求，都能被放进去。

类比：你有一个“充电口为 Type-C”的收纳盒。里面可以放手机、平板、耳机——它们是完全不同的产品，但只要都支持 Type-C 充电，就能放进这个盒子。USB 接口就是那个“Type-C 充电标准”。



2,
USB 接口里的方法没有方法体，那它到底有什么用？
答案：它是一份“行为契约”，规定了任何自称“USB设备”的类，必须具备哪些能力。

它不关心“怎么做”，只关心“能做什么”。所以不需要方法体。

它的价值体现在 Main.java 里：当你写 devices[i].connect() 时，你不需要知道 devices[i] 到底是鼠标还是键盘，你只需要知道它一定有 connect() 方法。这份安全感，就是接口给的。

类比：餐厅的菜单就是“接口”——上面写了“供应宫保鸡丁”，但没有写菜谱（方法体）。你作为顾客，看到菜单就知道能点这个菜，不需要关心后厨怎么炒。接口让“点菜的人”和“炒菜的人”可以独立工作，互不干扰。


3,
如果明天我想加一个 Printer 类也实现 USB 接口，Main.java 里需要改几行代码？
案：只需要改两行代码——而且都是“添加”，不是“修改原有代码”。

把数组长度从 2 改成 3：

java
USB[] devices = new USB[3];
在数组里多加一个元素：

java
devices[2] = new Printer();
循环体本身完全不需要动。这就是接口+循环组合的强大之处：对扩展开放（可以加新设备），对修改封闭（循环逻辑不用变）。这也是软件工程里著名的“开闭原则”的体现。
